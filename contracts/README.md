# contracts/

The **only** directory services may share. Services never import each other's code; they
depend on each other through the machine-readable contracts published here.

| Contract | Provider (owner) | Generated by | Consumers |
|---|---|---|---|
| `modbus/mock-modbus.devices.json` — every simulated device and register | `services/mock-modbus` | `make -C services/mock-modbus contract` | backend-ot dev seed (`tests/seed_db/mock_modbus_seed.py`) |
| `openapi/backend-ot.openapi.json` — backend-ot HTTP API (OpenAPI 3.1, from `create_app().openapi()`) | `services/backend-ot` | `make -C services/backend-ot contract` | `services/web-plusdas` (TypeScript types generated with `make -C services/web-plusdas api-types`; its `make test` fails while they are stale), optimizer *(future)* |

## Rules

- **The provider owns its contract.** Files here are generated from the provider's code and
  never edited by hand. Change the provider, regenerate, and commit both together.
- **Drift is a test failure.** Each provider has a unit test that the committed file equals what
  it would generate now (mock-modbus: `tests/test_contract.py`; backend-ot:
  `tests/unit/test_contract.py`). `make contracts-check` at the root regenerates every contract
  and fails if `contracts/` then differs from the git index; `make check` runs both, so stage
  regenerated contracts before running it.
- **Regenerate with the standard target `contract`:** `make -C services/<svc> contract`, or
  `make contract` at the root for every provider.
- **Consumers validate on read** (e.g. strict pydantic models with `extra="forbid"`), so a
  contract change is noticed instead of silently mis-parsed.
- **Breaking changes bump the version** and are called out in the commit, with consumers updated
  in the same change. Breaking = a removed or renamed route, field, register or enum value; a
  field that becomes required; a changed type or unit. Adding is not breaking. Where the version
  lives: mock-modbus → `CONTRACT_VERSION` in `app/contract.py`; backend-ot → `version=` in
  `create_app()` (`src/app.py`), published as `info.version`.
- **Consumers never import provider code**, and never read a provider's files outside
  `contracts/`. **Typed clients are generated, committed inside the consumer, and drift-checked
  by its tests.** web-plusdas uses openapi-typescript (types only) into
  `src/api/generated/backend-ot.ts`, imported only as `@contracts/backend-ot`. The consumer's
  build never reads `contracts/`, only the committed output. A Python consumer would follow the
  same pattern with its own generator (decided when one exists; it adds a dependency).
- The `contracts` skill (`.claude/skills/contracts/`) is the step-by-step for changing one.

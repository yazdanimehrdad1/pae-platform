# Change a contract

`contracts/` is the only thing services share (rules: `contracts/README.md`). Every file there
is **generated by its provider** and checked for drift, so a contract change is always:
change the provider's code → regenerate → classify → update consumers → commit together.

| Contract | Provider regenerates with | Drift test (in `make test`) | Version lives in |
|---|---|---|---|
| `contracts/openapi/backend-ot.openapi.json` | `make -C services/backend-ot contract` | `tests/unit/test_contract.py` | `version=` in `create_app()`, `src/app.py` |
| `contracts/modbus/mock-modbus.devices.json` | `make -C services/mock-modbus contract` | `tests/test_contract.py` | `CONTRACT_VERSION`, `app/contract.py` |

## Procedure

1. **Change the provider, not the contract.** Never hand-edit a file in `contracts/`. For a
   backend-ot endpoint use the `add-endpoint` skill; for a mock device use `add-mock-device`.
2. **Regenerate:** `make -C services/<provider> contract` (or `make contract` at the root for
   every provider).
3. **Read the diff:** `git diff -- contracts/`. Classify it:
   - **Additive (not breaking):** new route, new optional field/parameter, new response field,
     new enum value in a *response*, new device or register.
   - **Breaking:** a route, field, parameter, device or register removed or renamed; a field
     becomes required or changes type/format/unit; an enum value removed; a register's
     address, width, sign or scale changed; a status code a consumer relies on changed.
   - Doc-only (`description`, `summary`, `title`) changes are neither; no version bump.
4. **If breaking:** ask the user before going further (it's a design decision). Then bump the
   version (table above), regenerate again, and say so in the commit message.
5. **Update consumers in the same change.** Find them from the Consumers column of
   `contracts/README.md`, plus a search: `grep -rn "<contract file name>" services/`.
   Today: mock-modbus's map is read by backend-ot's dev seed
   (`services/backend-ot/tests/seed_db/mock_modbus_seed.py`, strict models in
   `src/schemas/tests_models/mock_modbus_contract.py`); backend-ot's OpenAPI spec is consumed
   by web-plusdas: run `make -C services/web-plusdas api-types` (regenerates
   `src/api/generated/backend-ot.ts`), then `make -C services/web-plusdas typecheck`. Every
   compile error there is a frontend call site the change affects, so fix them in the same
   change. `make -C services/web-plusdas test` fails while those types are stale. Work inside
   one service at a time; a consumer changes only its own files.
6. If a new service starts consuming a contract, add it to the Consumers column.

## Done when

- Regenerated files are staged (`git add contracts/`), then `make check` at the repo root
  passes: every service's lint + tests (including the drift tests and the consumers' tests),
  then `contracts-check`, which regenerates every contract, compares with the git index and
  prints `contracts/ is current`.
- For a mock-modbus change consumed by the seed: `make up && make seed && make e2e` at the root
  still reports every point agreeing with the contract (see the `run-platform` skill).
